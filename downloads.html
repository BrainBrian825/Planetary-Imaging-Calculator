Packages include the processing dependencies and denoising models; Python is not required to run the application.

01

Installation

macOS

Extract the ZIP and move Planetary Studio.app to Applications. Open it from Finder; it runs as a normal Dock application. The prebuilt native libraries require macOS 27 or newer on an Apple silicon Mac.

Because the community build is not notarized, macOS may require explicit approval in Privacy & Security. Camera access is needed only when using camera capture.

Windows

Extract the entire ZIP into a writable folder and run PlanetaryStudio.exe inside the PlanetaryStudio folder. Keep the _internal directory and other bundled files beside the executable.

This is a portable x64 application, not an installer. Vendor-camera support may also require the manufacturer's SDK and driver.

Linux

Extract the tar.gz for your processor, then run PlanetaryStudio/PlanetaryStudio. Release builds target Ubuntu 24.04 or a compatible/newer glibc distribution, with Qt's desktop runtime libraries available.

Direct USB cameras need appropriate device permissions or udev rules. See the build and runtime dependencies for details.

Older versions and source code

Older versions of Planetary Studio can be downloaded from GitHub Releases. Each release retains its platform packages and release notes. The public repository also contains the source code, license, build instructions, and issue tracker.

03

Release verification and current limits

What is checked before publication

Automated builds cover macOS arm64, Windows x64, Linux x64, and Linux arm64. Each platform runs the test suite, executes the packaged application's end-to-end self-test, then extracts and tests the portable archive before release publication.

Version 0.5.4 includes corrections for sensor-noise-driven registration errors and rectangular local stacking seams. These checks cover synthetic image truth, SER formats, image exports, protocols, and desktop behavior; they cannot validate hardware that is not physically present.

Build workflow and results · Validation details

Processing scope

The current engine supports calibration, frame trimming, object rejection, multiple quality estimators, manual alignment points, local frame ranking, wavelets, Richardson–Lucy deconvolution, and optional local FFDNet denoising. Export formats are 16-bit TIFF/PNG and floating-point FITS.

Drizzle reconstruction, planetary rotational derotation, and GPU acceleration are not implemented. This prerelease is not claimed to be a feature-for-feature or image-quality equivalent of PIPP, AutoStakkert, or waveSharp. FFDNet cleanup is off by default and can soften real detail.
